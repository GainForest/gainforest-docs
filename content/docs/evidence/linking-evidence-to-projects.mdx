The final step is to connect your uploads to a **Project**.

A Project is where your story, goals, updates, and evidence come together. Linking evidence helps other people understand what happened, where it happened, and what data supports your work.

<Callout type="success">
Good evidence is not just a file. It should include enough context for someone else to understand why it matters.
</Callout>

## Where evidence comes from

Evidence can come from the upload options covered in this section:

<Cards>
  <Card title="📸 Biodiversity observations">Species observations, field photos, dates, locations, and notes uploaded through Add observations.</Card>
  <Card title="🤖 Tainá observations">AI-assisted biodiversity observations created through Tainá on Telegram.</Card>
  <Card title="📦 Batch uploads">Larger datasets reviewed case by case, such as tree data, drone imagery, survey exports, field photo archives, or structured data.</Card>
  <Card title="🎙 AudioMoth bioacoustics">Sound recordings and deployment records from AudioMoth workflows.</Card>
</Cards>

## Link evidence from the Project page

On a Project page, users can add an update and attach optional evidence.

<Figure src="/assets/link-evidence-options.svg" alt="Project update interface showing evidence options" caption="Project updates can include text plus optional evidence such as images, sounds, trees, observations, files, or external links." />

You can use this when you want to:

* explain what the evidence shows
* add context around a field activity
* attach multiple records to a Project update
* share files, reports, or external links
* keep your Project timeline updated over time

## What can be linked as evidence?

The main evidence types should match the upload options covered in this section:

<Cards>
  <Card title="📸 Biodiversity observations">Species observations, field photos, dates, locations, and notes from the Add observations flow.</Card>
  <Card title="🤖 Tainá observations">Biodiversity observations created through Tainá, including AI-assisted species suggestions and field notes.</Card>
  <Card title="📦 Batch upload outputs">Reviewed batch data such as tree data, drone imagery, survey exports, field photo archives, or other structured data.</Card>
  <Card title="🎙 AudioMoth recordings">Sound recordings, deployment records, playable previews, or spectrograms from AudioMoth workflows.</Card>
</Cards>

You can also add supporting material directly from the Project update flow:

* write a short description or update explaining what happened
* add pictures or image files
* attach sounds or audio files
* attach videos
* attach documents, reports, audits, methodologies, certificates, or testimonials
* add external links to websites, dashboards, maps, reports, datasets, or other evidence platforms

## Accepted additional file formats

For direct file evidence, supported formats include:

<Cards>
  <Card title="📸 Images">JPG, PNG, GIF, WebP, AVIF, and SVG.</Card>
  <Card title="🎥 Video">MP4, WebM, MOV, and M4V.</Card>
  <Card title="🎙 Audio">MP3, WAV, M4A, OGG, FLAC, and AAC.</Card>
  <Card title="📄 Documents">PDF, text, Markdown, HTML, RTF, Word documents, spreadsheets, and presentations.</Card>
  <Card title="🔗 External links">HTTP or HTTPS links to reports, websites, dashboards, maps, datasets, or other evidence platforms.</Card>
</Cards>

When adding a file as evidence, users can choose a content type such as Document, Report, Audit, Evidence, Testimonial, Methodology, Photo, Video, Dataset, Certificate, Sound, or Other.

<Callout type="warning">
File evidence currently supports files up to **10MB** per file in the Project evidence flow. Datasets should generally use the **batch upload** process, especially if they are large, structured, or need GainForest team review before being linked to a Project.
</Callout>

## Link observations during upload

When adding observations, you can link them directly to a Project before publishing.

<Figure src="/assets/add-observations-link-project.webp" alt="Add observations form with project linking" caption="Use the Project selector to link observations to a Project." />

You can also upload observations first and link them to a Project later.

## Good evidence includes context

When linking evidence, add a short note if possible. Explain:

* what the evidence shows
* who collected it
* when it was collected
* where it was collected
* why it matters for the Project

This makes the evidence easier to understand for people who were not present during the fieldwork.

## Why this matters

Linked evidence helps a Project become more useful for:

* impact reporting
* grant applications
* partner updates
* community visibility
* funder review
* showing long-term stewardship
